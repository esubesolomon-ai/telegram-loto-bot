# Ethio Lottery Demo — Telegram Bot + Admin Web Dashboard

A demo-only reference implementation for the proposed six-digit random lottery. It includes a Telegram bot webhook and a browser-based admin dashboard in one Flask app. It is not licensed or approved for real-money gambling.

## Included features

- Telegram `/start`, `/rules`, `/draws`, `/buy`, `/mytickets` and menu buttons.
- Daily / Weekly / Monthly demo draws with the proposed displayed prices (100 / 50 / 50 ETB).
- Secure random six-digit ticket number, including leading zeroes; unique number per draw enforced by SQLite.
- Ticket receipt with a unique ticket code and visible DEMO / no-payment status.
- Admin login with hashed password, CSRF-protected forms, secure cookie settings, and 30-minute session lifetime.
- Dashboard for draw creation, closing sales, running a draw once, viewing tickets/players, a demo ledger, and audit events.
- Draw result is derived from a secret random seed and a SHA-256 commitment is recorded; seed is revealed after the demo result for verification.
- Editable no-match draw policy setting.
- Health check at `/health`.

## Important limitations

This is a starting demo, not production-ready lottery infrastructure. Do not accept deposits, sell paid entries, advertise cash prizes, or pay winners with it. Before real-money use, obtain applicable Ethiopian legal/licensing advice and payment-provider approval. Add age/eligibility controls, a reviewed published prize/refund policy, independent draw audit/certification as required, a reliable managed PostgreSQL database, tested backups, role-based finance and payout approvals, payment-provider verification/reconciliation, rate limits, monitoring, incident response, privacy/retention policies, and security testing.

- Render's free web service may sleep and its local filesystem/database is not reliable persistent storage. Data may be lost on restart/redeploy. Use this only for testing.
- Admin roles are represented in the database but this demo currently provides one owner login; do not share it. Multi-user role management and MFA should be implemented before a real launch.
- The dashboard records demo ticket amounts in a ledger, not actual money. It has no payment integration or payout feature.
- No admin action can edit or reroll an already drawn result through the interface.
- The Telegram webhook requires a publicly reachable HTTPS service and a secret header configured with Telegram.

## Deploy on Render (free demo)

1. Upload all files in this folder to the root of your GitHub repository, replacing the old polling bot files. `render.yaml` defines a **Web Service**, not a background worker.
2. In Render choose **New + → Blueprint**, select the repository, and review the service.
3. Enter the environment variables when prompted:
   - `BOT_TOKEN`: token from @BotFather. Never put it in GitHub or send it in chat.
   - `WEBHOOK_SECRET`: generate a long random secret containing only letters, digits, `_`, and `-` (Telegram's secret-token format).
   - `ADMIN_PASSWORD`: choose a unique strong password. Save it in a password manager.
   - `ADMIN_USERNAME`: keep `admin` or change it before deployment.
   - `APP_SECRET` is generated by the Blueprint.
4. Deploy and wait until `/health` reports `ok: true`.
5. Copy your Render service URL (for example `https://your-service.onrender.com`). Set Telegram webhook using this URL in a browser, substituting your actual bot token, service URL, and webhook secret:

   `https://api.telegram.org/botYOUR_BOT_TOKEN/setWebhook?url=https://YOUR-SERVICE.onrender.com/telegram/webhook&secret_token=YOUR_WEBHOOK_SECRET`

   Do not share the full URL; it contains the bot token. A successful response should include `"ok":true`.
6. Open `https://YOUR-SERVICE.onrender.com/admin/login`, then log in with `ADMIN_USERNAME` and `ADMIN_PASSWORD`.
7. Send `/start` to your Telegram bot, then test `/rules`, `/draws`, `/buy`, and `/mytickets` after creating a demo draw in the dashboard.

## Local run (optional)

Python 3.11+ recommended.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Set environment variables (see `.env.example`; this app does not automatically load `.env`) and run:

```bash
python app.py
```

## Draw behavior

- Tickets only exist for a particular draw.
- Sales must be manually closed by an admin in this demo; production should close automatically on the configured deadline.
- The admin may run a draw only after it is closed. The result is generated once, with no reroll when no ticket matches.
- If no ticket matches, this demo simply records zero matching tickets. It does not award or roll over a prize; publish a legally reviewed policy before real-money use.
- Time inputs in the dashboard are interpreted as UTC.

## Security reference notes

The admin password is stored as a password hash (Werkzeug's password hashing utilities), not plain text. Forms use session-bound CSRF tokens; admin session cookies are HttpOnly and SameSite=Lax and should be Secure on HTTPS. The webhook validates Telegram's `X-Telegram-Bot-Api-Secret-Token`. Review OWASP's password storage, authentication, session management, and logging guidance before extending the system.
